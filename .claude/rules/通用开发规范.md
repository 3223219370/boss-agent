# 通用开发规范

## 文件组织

- **一个 tsx 文件只写一个页面或模块**：每个 `.tsx` 文件只包含一个页面级组件或一个功能模块组件，禁止在同一个文件中定义多个页面或多个独立模块。页面内的子组件应拆分到独立文件中，通过 import 引入。
- **组件/页面必须用文件夹组织**：每个组件或页面必须是独立文件夹，文件夹名用 kebab-case，内部至少包含 `index.tsx`（组件逻辑）和 `index.module.scss`（CSS Modules 样式）。**禁止**直接在非文件夹路径下写 `组件名.tsx`，**禁止**把样式写在组件文件夹以外的文件中。

  ```
  // ✅ 正确
  UserCard/
    ├── index.tsx
    ├── index.module.scss
    └── types.ts        // 该组件 ≥2 个类型定义时

  // ❌ 禁止
  UserCard.tsx          // 组件没有独立文件夹
  UserCard/
    ├── UserCard.tsx    // 样式写在别处
  ```

- **组件** → 优先放在当前页面的 `components/` 下；被多个页面共用时提升到 `src/components/`
- **Hook** → 优先放在当前页面目录下；被多个页面共用时提升到 `src/hooks/`
- **工具函数** → 优先放在当前页面目录下；被多处复用时提升到 `src/utils/`
- **常量** → 优先放在当前页面目录下；被多处复用时提升到 `src/constant/`
- **TypeScript 类型定义** → 单个类型可留在文件顶部；≥2 个类型必须抽离到 `types.ts`
- **组件设计优先考虑通用性**：开发组件时 Props 接口预留扩展空间（使用可选属性、泛型），UI 不耦合特定页面业务逻辑，数据通过 Props 传入而非组件内部写死获取。当组件可能被多个页面使用时，优先放到 `src/components/` 下。
- **API 调用** → 统一放在 `src/services/` 下（按业务域拆分）
- **常量** → 优先放在当前 page 下的 `constant.ts` 文件；被多个页面/模块共用的通用常量提升到 `src/constant/` 下

```typescript
// ✅ 页面级常量 — pages/Anniversary/constant.ts
export const TYPE_PRESETS = ['恋爱', '结婚', '求婚', '生日', '旅行', '初见', '告白']

// ✅ 通用常量 — src/constant/error-code.ts
export const AUTH_ERROR_CODES = [1004, 1011]
```

## 命名规范

| 类型 | 风格 | 示例 |
|------|------|------|
| 组件 | PascalCase | `UserCard` |
| 函数/变量 | camelCase | `fetchUser` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRY` |
| 文件 | kebab-case | `user-card.tsx` |
| Hook | camelCase + use 前缀 | `useAuth` |

- 命名应简洁且有意义，**优先完整单词而非缩写**
- 当命名过长（超过 25 个字符）时，使用团队约定的缩写，但缩写需保持可读性

## 组件结构

组件内部按以下顺序组织：

```typescript
interface Props {
  userId: string;
  onSuccess?: () => void;
}

function UserCard({ userId, onSuccess = noop }: Props) {
  // 1. Hooks
  const query = useUser(userId);

  // 2. 派生状态
  const isActive = query.data?.status === 'active';

  // 3. 事件处理器
  const handleClick = () => { onSuccess(); };

  // 4. 条件返回（Loading / Error / Empty）
  if (query.isLoading) return <Skeleton />;
  if (query.isError) return <ErrorCard err={query.error} />;

  // 5. 主 JSX
  return <div onClick={handleClick}>{query.data?.name}</div>;
}
```

## 控制流与语法

**原则：代码标准、简洁、高效，减少认知负担。**

### 分支与条件

- **guard clause 优先**：提前 `return/throw/continue`，减少嵌套层级
- **短路替代简单 if**：`cond && action()`；复杂分支/多语句块保留 `if`
- **复杂条件先命名**：提取为语义化布尔值 `const shouldX = ...`
- 简单分支可用三元，**禁止嵌套多层三元**

```typescript
// ✅ guard clause
if (!user) return null;
if (!hasPermission) throw new ForbiddenError();
// 主逻辑...

// ✅ 复杂条件命名
const shouldRedirect = !isAuthed && !isPublicPath;
if (shouldRedirect) navigate('/login');
```

### 数据结构替代冗长判断

**强制规则：当同一变量/表达式与 ≥2 个值做 `===` / `||` 比较时，必须用数组/Set 替代，禁止写 `||` 链。** 这包括但不限于：值比较、`typeof` 检查、枚举判断等所有场景。

- 多值匹配：`[...].includes(x)` 或 `new Set([...]).has(x)`
- 多分支映射：`handlers[type]?.()` / 对象 Map

```typescript
// ❌ 禁止：值比较 || 链
if (status === 'pending' || status === 'review' || status === 'draft') { ... }
// ✅
const editableSet = new Set(['pending', 'review', 'draft']);
if (editableSet.has(status)) { ... }

// ❌ 禁止：typeof || 链
if (typeof value === 'string' || typeof value === 'number' || typeof value === 'boolean') { ... }
// ✅
const primitiveTypes = new Set(['string', 'number', 'boolean']);
if (primitiveTypes.has(typeof value)) { ... }

// ❌ 禁止：switch/if-else 映射链
if (type === 'add') handleAdd();
else if (type === 'edit') handleEdit();
else if (type === 'del') handleDel();
// ✅ 对象映射
const handlers = { add: handleAdd, edit: handleEdit, del: handleDel };
handlers[type]?.();
```

### 现代语法

- 优先使用 `?.`、`??`、`??=`、`||=`、解构/默认参数、模板字符串
- 优先数组/对象方法：`map/filter/reduce/find/some/every`、`Object.entries/fromEntries` 替代手写循环

```typescript
// ✅ 可选链 + 空值合并
const city = user?.address?.city ?? '未知';

// ✅ 解构 + 默认值
const { page = 1, size = 20 } = params;

// ✅ 数组方法链式调用
const activeNames = users
  .filter(u => u.isActive)
  .map(u => u.name);
```

### 函数设计

- 单一职责，一个函数只做一件事
- 参数 ≤ 3 个，超过时用对象参数 + 解构
- 避免副作用：纯函数优先，副作用集中管理
- 避免过早抽象：重复 2 次以上再提取

## 注释规范

- TS `interface` / `type` 的**每个属性必须加 JSDoc 注释**说明含义（见 TypeScript 规范示例）
- 组件 Props 接口、复杂业务逻辑块、非显而易见的业务规则处添加清晰中文注释
- 注释重点解释：**业务规则、边界条件、为什么这么做**
- 禁止逐行注释 / 翻译 JSX / 对显而易见代码重复注释
- **状态与组件必须注释**：所有 `useState`、`useRef`、`useMemo`、`useCallback` 等 Hook 声明的状态变量，以及页面中使用的子组件，必须在声明/导入处添加注释说明其用途。注释写在声明语句上方。

## 样式规范

- **样式方案**：组件使用 CSS Modules（`index.module.scss`），全局样式使用 `src/styles/global.scss`
- **TSX 导入方式**：`import styles from './index.module.scss'`，类名用 `styles.xxx` 引用
- **禁止内联样式**（`style={{}}`），除非是动态计算值（如进度条宽度）
- **类名命名**：CSS Modules 中使用 camelCase，简短描述用途（如 `.card`、`.header`、`.itemActive`）
- **布局优先 Flexbox / Grid**：避免使用 `float`、绝对定位做布局
- **组件间距由父级控制**：组件自身不设 `margin`，由父容器通过 `gap`、`padding` 控制
- **响应式设计**：优先使用相对单位（`100%`），避免固定 `px`（除 `1px` 边框等场景）
- **动画仅用 `transform` 和 `opacity`**，交互反馈使用 `transition`（150-300ms）

> 详细的样式系统架构、Token 定义、主题切换、CSS Modules 编写规则等指导，参见《[样式设计规范](./样式设计规范.md)》

## TypeScript 规范

- 禁用 `any`，类型必须完整
- 禁用 `var`，优先 `const`
- 显式标注函数签名和导出 API，不标注可推断的变量
- `interface` 描述对象类型，`type` 用于联合/交叉类型
- **定义 interface / type 时，每个属性必须加 JSDoc 注释说明含义**

```typescript
// ✅ 每个属性都有注释
interface UserDTO {
  /** 用户唯一标识 */
  id: string;
  /** 用户昵称，最长 20 字符 */
  nickname: string;
  /** 账号状态 */
  status: 'active' | 'frozen' | 'deleted';
  /** 上次登录时间，ISO 8601 格式 */
  lastLoginAt: string;
}
```
